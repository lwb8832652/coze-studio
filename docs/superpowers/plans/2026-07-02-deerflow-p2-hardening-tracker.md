# DeerFlow P2 Hardening Tracker

> Phase 2 starts after P0/P1 parity stabilization has been merged to `dev`.
> Keep this tracker focused on production hardening and the small visible
> parity debts explicitly deferred from P1. Do not reopen P0/P1 mainlines
> unless a direct regression is found.

## Goal

Turn the DeerFlow-parity task experience into a production-grade baseline
without drifting away from the DeerFlow visible workflow. P2 work is split into
small independently verifiable slices so testing can continue incrementally.

## Scope Rules

- Keep task vocabulary: `新建任务`, `全部任务`, `我的任务`, `任务详情`,
  `任务记忆`.
- Keep Go-native Eino ADK execution. Do not add a Python sidecar.
- No IM Channels.
- Favor visible DeerFlow parity debts before broad platform hardening.
- Any task-detail change must reference a case id from
  `docs/superpowers/plans/2026-06-28-deerflow-task-detail-parity-validation.md`.
- Security, observability, and policy work must remain metadata-only at UI/API
  boundaries unless a separate user-reviewed contract says otherwise.
