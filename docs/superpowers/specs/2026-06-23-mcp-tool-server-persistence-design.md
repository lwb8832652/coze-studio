# MCP Tool Server Persistence Design

## Goal

M6.1 makes Workbench MCP tool configuration durable. The current in-memory
catalog is useful for tests and early UI wiring, but production Skill grants
and future Eino MCP execution need MCP server/tool metadata to survive process
restarts.

## Scope

- Add a MySQL-backed implementation of the existing `mcptool.Catalog`
  interface.
- Persist one MCP server row per `server_id`.
- Store the current API shape without changing Workbench handlers:
  - server identity and space ownership;
  - name, description, type, enabled status;
  - JSON `config`;
  - JSON `auth`;
  - JSON `tools`;
  - created/updated timestamps;
  - `deleted_at` for future soft-delete lifecycle.
- Use the MySQL catalog in application bootstrap.
- Keep `InMemoryCatalog` for unit tests and non-production harnesses.
- Add Atlas migration and schema snapshot entries.

## Table

`mcp_tool_servers`

- `server_id`: primary key, generated by the application ID generator.
- `space_id`: workspace/tenant scope.
- `name`, `description`, `server_type`, `enabled`: display and runtime
  classification metadata.
- `config`: JSON transport configuration.
- `auth`: JSON auth configuration. This is only a storage placeholder in this
  slice; secret encryption and masked round trips remain separate work.
- `tools`: JSON array of `MCPToolDefinition` values.
- `created_at`, `updated_at`: millisecond timestamps.
- `deleted_at`: bigint soft-delete marker, default `0`.

Indexes:

- `idx_mcp_tool_servers_space_updated(space_id, updated_at)`
- `idx_mcp_tool_servers_space_enabled(space_id, enabled, deleted_at)`

## Boundaries

This slice does not make MCP execution production-ready by itself. The durable
catalog must not be treated as a complete Tool Registry. Coze still owns:

- OAuth lifecycle;
- encrypted secret storage and masked API responses;
- transport/session lifecycle;
- stdio sandboxing and command allow-lists;
- health checks;
- tool authorization and policy;
- audit records;
- timeout and output budgets;
- Eino MCP adapter invocation.

## Compatibility

The Workbench MCP API remains unchanged. `UpsertServer`, `GetServer`,
`ListServers`, and `TestCall` continue to operate through the `Catalog`
interface. Existing tests can still install an in-memory catalog explicitly.

The Skill tool candidate provider from M5.8 automatically benefits from
durable MCP rows because it reads through the same catalog interface.
