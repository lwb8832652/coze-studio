# 任务标题生成优化设计

## 背景

当前 Workbench 在创建任务时，如果调用方没有显式传入标题，后端会直接使用
首条用户消息作为初始标题。技能创建等场景会把 `@skill-creator`、固定引导语
和完整问题一起展示在标题栏，信息密度过高，也容易让用户误以为这是模型生成
的最终标题。

首轮任务成功后，现有 Agent Runtime 已支持模型生成标题，并通过
`context.thread_title_updated` 事件更新前端。本次优化保留这条异步链路，只
调整初始标题和模型失败时的兜底质量。

## 目标

- 任务创建后立即展示可辨识、简洁且不包含资源调用标记的临时标题。
- 首轮任务成功后继续使用模型生成的语义标题替换临时标题。
- 模型不可用、返回空内容或生成失败时，不再退回完整原始问题。
- 用户手动修改过标题后，异步生成结果不得覆盖用户标题。
- 不修改 API、数据库结构、任务路由和前端事件合同。

## 非目标

- 不在任务创建请求中同步调用模型。
- 不为历史任务批量重算标题。
- 不新增用户侧标题生成配置。
- 不改变后续对话的标题更新策略。

## 方案

### 初始标题

服务端从首条用户消息生成临时标题：

1. 移除 `@skill-creator` 等独立资源调用标记。
2. 合并多余空白并清理首尾标点。
3. 对已知技能创建引导语提取核心意图，使用“创建技能”作为稳定临时标题。
4. 其他消息最多保留 32 个 Unicode 字符，超出时添加省略号。
5. 清理后为空时使用“新建任务”。

显式传入的标题只做空白归一化和长度保护，不应用消息意图改写。

### AI 标题

首轮主任务成功后，沿用现有 `RunProcessor` 标题生成流程：

1. 优先采用执行结果中显式返回的标题。
2. 否则调用当前 Run 选定的模型，根据用户问题和助手回答生成短标题。
3. 发送给标题模型前移除资源调用标记，提示词明确禁止输出工具、技能标记和
   解释文字。
4. 模型失败时使用与初始标题相同的确定性清理逻辑兜底。
5. 仅当线程标题仍等于创建时的临时标题，才允许写入生成结果。

标题更新继续在 Run 成功事务中落库，并发出
`context.thread_title_updated`，前端不新增第二套状态。

## 错误与并发处理

- 标题模型失败不影响任务成功状态和回答落库。
- 模型返回空白、思考标签或仅资源标记时进入确定性兜底。
- 标题生成期间用户已手动改名时，现有 expected-title 条件更新拒绝覆盖。
- 子智能体和子 Run 不生成线程标题。
- 标题事件仍是隐藏同步事件，不作为对话步骤展示。

## 测试

- 创建技能消息生成“创建技能”，且不包含 `@skill-creator`。
- 普通长消息生成带省略号的 32 字符临时标题。
- 仅包含资源标记的消息生成“新建任务”。
- 显式标题不会被技能创建规则改写。
- 标题模型提示词不包含资源调用标记，并约束只返回短标题。
- 模型失败时使用清理后的确定性标题。
- 用户标题已修改时不写入异步生成标题。
- 既有标题事件和任务详情标题同步测试继续通过。

## 验收标准

- 新建技能任务进入详情页后，标题栏不展示完整引导语或
  `@skill-creator`。
- 首轮回答完成后，标题自动更新为语义化短标题。
- 模型异常时任务仍正常完成，标题保持简洁且可辨识。
- 手动修改标题后不会被后台生成结果覆盖。
