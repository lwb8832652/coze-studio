# 对话详情体验重设计

## 1. 背景

当前任务对话详情页已经具备完整的任务执行、对话、Token 用量、导出、详情、
收藏、分享、通知和继续追问能力，但主要内容缺少稳定的阅读主轴。用户消息、
Agent 执行过程、回复正文和用量信息处于接近相同的视觉层级，长回复会横跨
大面积画布，输入区也偏重。

本次设计面向 C 端用户，目标是在不减少任何现有功能的前提下，重新组织页面
的信息层级，让对话更像一段清晰、可信、可持续阅读的交流。

## 3. 目标与非目标

### 3.1 目标

1. 建立宽度稳定、适合长文本的对话阅读主轴。
2. 清晰配对用户请求、Agent 执行状态和最终回复。
3. 降低执行步骤与 Token 信息对正文阅读的干扰。
4. 保留全部已有功能和数据，不改变后端任务、消息和用量合同。
5. 继续复用首页与详情页的同一个输入组件。
6. 统一详情抽屉、用量抽屉、导出菜单和分享弹窗的视觉规范。
7. 覆盖桌面端、窄屏和移动端，以及加载、流式输出、失败和空态。

### 3.2 非目标

1. 不改变 Agent 执行流程、任务状态机或消息生成方式。
2. 不新增计费、费用预估、订阅或额度购买能力。
3. 不暴露原始工具参数、工具结果、隐藏提示词、凭证或内部审计数据。
4. 不重写首页输入框，不创建详情页专用输入组件。
5. 不改造左侧导航的信息架构。

## 4. 核心设计原则

### 4.1 功能等价重排

本次只调整展示层级和交互入口，不删除功能。现有能力必须能在新页面中找到
等价入口，已有数据必须继续可访问。

### 4.2 阅读优先

回复正文是页面主内容。执行步骤、Token、复制和反馈等辅助信息默认降低
权重，在用户需要时再展开。

### 4.3 一个共享输入组件

首页和详情页继续使用同一个 `ChatComposer`。组件支持两种表现密度：

- `hero`：首页使用，输入区域更高，承担首次任务创建。
- `docked`：详情页使用，输入区域紧凑并固定在阅读主轴底部。

两种形态共用相同的 DOM 结构、状态管理、快捷键、附件、模式、拓展、上下文、
模型选择、发送、禁用、加载和自动增高逻辑。形态差异只来自显式表现属性和
布局令牌，禁止复制业务逻辑。

## 5. 页面结构

### 5.1 顶部任务栏

顶部任务栏保持固定，内容包括：

- 当前任务标题；
- 导出；
- 详情；
- 收藏；
- 分享；
- 通知；
- 当前账号头像。

原顶部 Token 入口移除，避免与右下角用量入口重复。任务栏按钮统一为低噪声
线性图标和文字，不与对话正文竞争。

#### 5.1.1 共用通知与账号操作

右上角通知和头像必须与首页复用同一套功能组件，禁止在任务详情页复制通知
面板、账号菜单或状态逻辑。

- 首页与任务详情共用通知数据源、未读数量、已读状态和通知弹层；
- 两处共用账号头像、账号菜单、个人设置、退出登录和系统管理可见性；
- 在一个页面完成已读、头像或账号状态更新后，另一页面应立即保持一致；
- 键盘行为、焦点管理、ARIA 名称、加载态和错误态完全一致；
- 页面只负责右侧操作簇的摆放，不拥有通知或账号业务状态。

如果当前首页组件包含整块顶部栏，应从现有实现中抽取
`WorkspaceHeaderActions` 等共享操作簇，由首页和任务详情共同引用，而不是
让任务详情嵌套一整块首页顶栏。

### 5.2 对话阅读主轴

- 桌面端主轴宽度为 `720–780px`。
- 主轴在可用内容区内居中，不跟随超宽窗口无限拉伸。
- 中文正文使用 `15–16px` 字号和 `1.75–1.85` 行高。
- 长文本每行建议不超过约 65 个中文字符。
- 相邻轮次使用间距和轻分隔线区分，不为每条消息增加重型卡片。

### 5.3 用户消息

- 右对齐，使用中性浅灰消息气泡。
- 气泡宽度随内容变化，最大宽度不超过阅读主轴的 `72%`。
- 时间和状态为弱化辅助信息。
- 用户消息与对应 Agent 回复保持紧密的垂直关系。

### 5.4 Agent 回复

- 使用产品真实头像、`NewX AI · Agent` 名称和时间。
- 正文直接排版在基础页面表面，不默认包裹大卡片。
- 支持标题、段落、列表、表格、代码块、引用、文件和产物。
- 复制、点赞、点踩及更多操作位于回复末尾，默认低对比度。
- 流式生成时保留稳定内容宽度，避免回复区域横向跳动。

### 5.5 执行过程

每轮 Agent 回复顶部显示一条紧凑执行状态：

`已完成 2 个步骤 · 可用技能目录`

- 默认折叠；
- 执行中展示当前步骤和轻量进度；
- 点击后展开经过审核的步骤名称、状态、耗时和安全摘要；
- 不在对话 UI 暴露原始工具参数、工具响应、对象存储地址或内部运行配置；
- 失败时在同一位置展示错误摘要和重试入口。

## 6. Token 用量

### 6.1 默认入口

- 每个已创建的任务/对话详情页只有一个用量入口；
- 入口位于共用输入框右下角，文案格式为 `用量 29.9K`；
- 首页和尚未生成回复的新对话不展示；
- 第一轮回复产生用量后出现；
- 切换任务时随当前任务数据更新。

### 6.2 汇总 Popover

桌面端点击用量入口后向上展开 Popover：

- 建议宽度约 `300px`，高度随内容变化；
- 圆角 `12px`；
- 内边距 `20px`；
- 使用轻边框和克制阴影；
- 标题为 `Token 用量`；
- 展示当前对话总量、输入、输出和当前回复总量；
- 不展示费用估算；
- 底部提供 `查看用量明细`。

Popover 支持再次点击、点击外部和 `Esc` 关闭，并具备完整键盘焦点状态。

### 6.3 用量明细抽屉

`查看用量明细` 打开右侧抽屉，不新增独立页面：

- 桌面端宽度建议 `420–480px`；
- 顶部展示对话总量；
- 下方按对话轮次列出输入、输出和总量；
- 每轮可定位回对应消息；
- 数据加载失败时提供重试；
- 空数据时解释尚未产生可统计用量。

移动端不使用右侧抽屉，改为全宽底部抽屉。

## 7. 共用输入组件

### 7.1 `hero` 形态

- 用于首页；
- 保持当前较高输入区域和欢迎场景；
- 不显示当前对话用量；
- 继续支持模板入口和首次任务创建。

### 7.2 `docked` 形态

- 用于任务详情；
- 固定在阅读主轴底部；
- 默认紧凑，随输入内容自动增高；
- 不遮挡最后一条回复；
- 预留足够底部安全间距；
- 右下角承载当前对话用量入口。

### 7.3 共同行为

- 附件上传；
- Pro/模式选择；
- 拓展；
- 上下文选择；
- 模型选择；
- `@` 上下文；
- 发送、停止生成和重新生成；
- `Enter` 发送、`Shift + Enter` 换行；
- 禁用、加载、上传失败和超限反馈；
- 输入草稿保留和任务切换隔离。

## 8. 关联子页面与弹层

### 8.1 任务详情抽屉

承载任务状态、创建时间、更新时间、来源、执行摘要和允许展示的运行信息。
技术字段使用用户能理解的名称，不展示内部合同。

### 8.2 导出

- 简单格式选择使用轻量菜单；
- 需要文件范围、格式或高级选项时再进入中型弹窗；
- 导出中、成功和失败状态都有明确反馈。

### 8.3 分享

使用中型弹窗，按顺序展示：

1. 分享范围；
2. 链接或目标成员；
3. 权限说明；
4. 复制链接和确认操作。

### 8.4 统一弹层规范

- 圆角统一为 `12px`；
- 内边距为 `20–24px`；
- 区块间距为 `16px`；
- 固定标题、内容和操作区层级；
- 每个弹层最多一个主操作；
- 关闭、取消和返回行为保持一致；
- 危险操作需要明确确认，不依赖颜色作为唯一提示。

## 9. 响应式设计

### 9.1 窄屏桌面和平板

- 阅读主轴使用可用宽度并保留 `24px` 边距；
- 顶部次要操作收进更多菜单；
- 左侧导航可折叠；
- 输入框保持完整主要能力。

### 9.2 移动端

- 左侧导航切换为抽屉；
- 顶部只保留返回、标题、更多和头像；
- 用户气泡最大宽度提升到 `86%`；
- Agent 正文使用全宽阅读；
- Popover、详情抽屉和分享弹窗统一切换为底部抽屉；
- 输入组件固定底部并适配安全区；
- 键盘弹出时不遮挡输入内容和发送按钮。

## 10. 状态设计

必须覆盖以下状态：

- 初始加载；
- 历史消息增量加载；
- 流式输出；
- Agent 执行中；
- 用户取消；
- 单轮失败和重试；
- 任务级失败；
- 附件上传中和上传失败；
- 无 Token 数据；
- 用量加载失败；
- 超长文本；
- 代码、表格和文件产物；
- 网络断开和恢复；
- 只读任务；
- 无权限和任务不存在。

失败状态应尽量局部化，避免单条消息失败导致整个任务页不可用。

## 11. 可访问性

- 主要文字和背景达到 WCAG AA 对比度；
- 所有图标按钮提供可读名称；
- Popover、菜单、抽屉和弹窗具备正确 ARIA 角色；
- 打开弹窗或抽屉时管理焦点，关闭后返回触发入口；
- Popover 支持键盘进入、退出和 `Esc` 关闭；
- 状态不能只依赖红绿颜色；
- 流式更新使用克制的实时区域，避免读屏连续打断；
- 点击目标不小于 `40px`。

## 12. 组件边界

建议保持以下边界：

- `ChatDetailShell`：页面布局、顶部栏和响应式框架；
- `WorkspaceHeaderActions`：首页与任务详情共用的通知和账号操作簇；
- `ConversationViewport`：滚动、历史加载和定位；
- `ConversationTurn`：配对用户请求、执行状态和 Agent 回复；
- `ExecutionSummary`：折叠后的执行步骤；
- `AgentResponse`：安全渲染回复和回复操作；
- `ChatComposer`：首页与详情共用的输入组件；
- `UsageTrigger`：右下角用量入口；
- `UsagePopover`：用量汇总；
- `UsageDetailDrawer`：按轮次展示明细；
- `TaskDetailDrawer`：任务属性；
- `ExportMenu`、`ShareDialog`：关联操作。

页面组件负责组合，业务数据继续由现有任务和消息 hooks/service 提供。展示
组件不直接拼接 API 请求。

## 13. 功能等价清单

实施后必须保留：

- 对话累计 Token；
- 每轮输入、输出和总量；
- 执行流程和技能步骤；
- 回复复制、点赞和点踩；
- 导出；
- 详情；
- 收藏；
- 分享；
- 通知；
- 首页与详情共用的通知未读状态和通知弹层；
- 首页与详情共用的头像和账号菜单；
- 附件；
- 模式；
- 拓展；
- 上下文；
- 模型选择；
- 发送和停止；
- 失败、重试和长内容展示。

任何入口迁移都必须有可发现的新入口和测试覆盖，不能以“视觉简化”为理由
删除能力。

## 14. 验收标准

1. 桌面端对话正文宽度稳定，长文本不再横跨整个主内容区。
2. 用户请求与对应 Agent 回复能在一次扫视中正确配对。
3. 执行步骤默认折叠，展开后仍不暴露敏感内部数据。
4. 每轮回复不再常驻展示 Token 行。
5. 右下角用量显示当前对话累计值。
6. Popover 展示输入、输出、当前回复和总量。
7. 用量抽屉可以按轮次查看原有明细。
8. 首页和详情页确认复用同一输入组件。
9. 首页 `hero` 形态保持现有功能和布局。
10. 详情页 `docked` 形态不遮挡最后一条消息。
11. 导出、详情、收藏、分享和通知全部可用。
12. 首页和任务详情使用同一个通知/账号操作组件。
13. 两个页面的未读数、已读操作和账号状态保持同步。
14. 桌面、窄屏和移动端不存在横向溢出。
15. 键盘可以完成输入、发送、打开用量、查看明细和关闭弹层。
16. 加载、流式输出、失败、重试、空态和只读状态均有明确反馈。

## 15. 验证建议

- 为 `ChatComposer` 两种形态补组件测试，确认共用逻辑不分叉；
- 为用量汇总和按轮次明细补数据映射测试；
- 为 Popover、抽屉、菜单和弹窗补键盘及关闭行为测试；
- 为首页和详情共用通知/账号操作簇补状态同步和交互回归测试；
- 为执行中、失败、重试、长回复和历史加载补页面测试；
- 使用 Codex 内置浏览器在桌面和窄屏验收真实任务；
- 对比改造前截图和最终视觉目标，检查阅读宽度、消息配对、用量位置、
  输入框结构及弹层层级；
- 检查浏览器控制台、网络失败反馈和无权限路径。
