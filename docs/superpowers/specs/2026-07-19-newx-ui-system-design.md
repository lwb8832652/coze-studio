## 2. 背景与问题

当前项目已经形成多套并行视觉语言：

- 工作台接近大留白内容型页面；
- 资源库使用传统 Coze 表格；
- 技能管理使用绿色品牌卡片；
- 网页应用开发使用蓝灰渐变卡片；
- 工作空间和系统管理使用紫色高亮；
- 部分页面使用全局 `workspace-prototype.less`，工作台和 AppDev 又维护独立
  样式。

这些页面在功能上可以使用，但标题结构、页面宽度、主色、圆角、控件高度、
图标、列表密度、空态和反馈状态缺少共同规则。继续按页面追加私有样式会进
一步扩大差异，也会提高后续功能迭代和验收成本。

本次重构的目标不是替换现有信息架构，也不是把所有页面强制做成同一种布局，
而是建立一套覆盖全部页面类型的视觉系统和组件边界。

## 3. 已确认的设计方向

采用简洁、克制的浅色生产工具风格：

- 暖白画布和白色主表面；
- 深色正文；
- 单一墨绿色品牌主色；
- 细分割线和轻量层级；
- 阴影只用于浮层，不依赖阴影区分普通内容；
- 模板和数据列表优先使用行结构，卡片只用于真正独立的业务对象；
- 保留当前导航和高频操作位置。

未采用另外两种方向：

- 蓝色技术工作台方向辨识度清晰，但与当前 NewX 绿色品牌不一致；
- 暖色双栏卡片方向更亲和，但页面对象密度偏高，容易重新形成卡片堆叠。

## 4. 目标

### 4.1 产品目标

- 所有页面看起来属于同一个产品；
- 高频页面在长时间使用时保持清晰、安静、低干扰；
- 新功能优先组合共享组件和 token，不再复制页面私有视觉规则；
- 保持现有业务能力、路由、权限和数据契约不变；
- 桌面、窄桌面和平板宽度下保持核心操作可用；
- 登录注册页在移动宽度下可独立使用。

### 4.2 非目标

- 不调整菜单名称、顺序和权限边界；
- 不重做任务、Skill、MCP、AppDev、系统管理的数据模型；
- 不新增业务功能；
- 不为了视觉统一把表格全部改成卡片，或把卡片全部改成表格；
- 不更换 Semi/Coze Design 组件体系；
- 不引入长期并存的第二套主题。

## 5. 设计原则

### 5.1 功能结构优先

页面先满足任务完成，再考虑装饰。筛选、搜索、分页、批量操作、创建、编辑、
删除、错误重试和权限提示必须保持原有行为。

### 5.2 同系统，不同页面类型

页面共享颜色、字体、尺寸、图标和状态规则，但根据业务选择合适结构：

- 高密度数据使用表格或行列表；
- 内容浏览使用有限卡片；
- 编辑器使用专业分栏；
- 设置使用侧边导航加表单；
- 对话和任务详情使用内容工作台。

### 5.3 先层级，后装饰

区分内容的优先顺序：

1. 间距、对齐和文字层级；
2. 分割线；
3. 轻微表面色差；
4. 边框；
5. 阴影。

### 5.4 单一主色

墨绿色只用于品牌、主操作、选中项和少量强调。业务状态使用语义色，不能用
随机彩色渐变代替层级。

### 5.5 可访问性优先

交互不能只靠颜色区分。键盘焦点、禁用、加载、错误和选中状态必须清晰。

## 6. 设计 Token

### 6.1 颜色

```less
:root {
  --newx-brand-700: #075a34;
  --newx-brand-600: #0b7442;
  --newx-brand-500: #148a50;
  --newx-brand-100: #dff3e7;
  --newx-brand-50: #f3faf6;

  --newx-canvas: #f7f8f6;
  --newx-surface: #ffffff;
  --newx-surface-subtle: #f3f5f3;
  --newx-surface-hover: #edf2ef;
  --newx-surface-active: #e4eee8;

  --newx-text-primary: #18201d;
  --newx-text-secondary: #59635e;
  --newx-text-tertiary: #858f89;
  --newx-text-disabled: #b4bbb7;

  --newx-border: #e1e6e3;
  --newx-border-strong: #cbd4cf;
  --newx-focus: #2f6fed;

  --newx-success: #168a4c;
  --newx-warning: #c77b08;
  --newx-danger: #d94b45;
  --newx-info: #2f6fed;
}
```

约束：

- 紫色不得再作为页面主色或选中态；
- 蓝色只用于信息语义和键盘焦点；
- 背景不能使用大面积 AI 渐变；
- 代码编辑器内容区可以保留专业深色主题，但编辑器外壳仍使用全局 token。

### 6.2 字体

继续使用项目已有中文字体栈：

```css
font-family: 'PingFang SC', 'Noto Sans SC', sans-serif;
```

字号层级：

| 用途 | 字号/行高 | 字重 |
| --- | --- | --- |
| 页面标题 | 24/32 | 600 |
| 一级区块标题 | 20/28 | 600 |
| 二级区块标题 | 16/24 | 600 |
| 正文 | 14/22 | 400 |
| 控件文字 | 14/20 | 500 |
| 辅助信息 | 12/18 | 400 |

页面标题不混用超大字号、英文眉题和装饰性字体。英文技能名、模型名和代码保
留原文，但不改变整体中文排版节奏。

### 6.3 间距

使用 `4px` 基础网格：

```text
4 / 8 / 12 / 16 / 20 / 24 / 32 / 40 / 48
```

- 控件内部间距优先使用 `8` 和 `12`；
- 普通区块间距使用 `16` 或 `24`；
- 页面级间距使用 `24` 或 `32`；
- 不允许页面自行新增 `13px`、`18px`、`27px` 等离散间距。

### 6.4 圆角

```less
--newx-radius-sm: 8px;
--newx-radius-md: 10px;
--newx-radius-lg: 12px;
--newx-radius-xl: 16px;
--newx-radius-pill: 999px;
```

- 输入框、按钮、标签：`8px` 或 `10px`；
- 内容表面、弹窗：`12px`；
- 大型独立容器：最多 `16px`；
- 列表行不单独使用大圆角卡片。

### 6.5 控件尺寸

- 标准按钮、输入框、选择器：`40px`；
- 紧凑工具栏：`32px`；
- 大型主操作：`44px`；
- 图标按钮点击区：不得小于 `32x32px`；
- 表格行高：默认 `56px`，信息较多时 `64px`；
- 标签高度：`24px`。

### 6.6 阴影

普通页面和卡片默认无阴影。仅以下场景允许：

- 下拉菜单；
- Popover；
- Modal/Drawer；
- 拖拽浮层；
- 需要覆盖底层内容的固定工具条。

## 7. 图标与头像

### 7.1 图标规则

- 优先使用 `@coze-arch/coze-design/icons`；
- 同一页面不能混用多套图标；
- 标准图标为 `16px`、约 `1.5px` 视觉线宽；
- 空态插图可以更大，但不能用 Emoji 代替功能图标；
- 菜单项、按钮和状态不得因图标缺失只靠缩进或颜色表达语义。

硬性规则：

- `任务中心`必须显示独立的任务清单图标；
- `全部任务`使用任务记录/文档类图标，与 `任务中心`区分；
- 最近任务必须使用一致的完成、等待、取消、异常状态图标；
- 搜索、排序、附件、模式、工具、模型、上下文、发送、收藏、统计、行跳转、
  通知和更多操作必须有统一图标。

### 7.2 头像规则

- 右上角快捷头像和左下角账户头像均保留；
- 两处必须来自同一用户数据源和同一头像资产；
- 头像图片、首字母、背景色和裁切规则保持一致；
- 右上角可因工具栏高度使用较小尺寸，但不能显示成另一个用户；
- 右上头像保持现有身份展示/交互，不新增重复账户菜单；
- 账号设置和退出登录仍只放在左下角账户菜单。

## 8. 全局应用骨架

### 8.1 左侧导航

- 展开宽度：`264px`；
- 收起宽度：`72px`；
- 顶部区域承载空间切换和折叠；
- 主导航保持当前名称和顺序；
- `任务中心`和 `全部任务`的层级关系同时使用缩进、图标和选中态表达；
- 最近任务区域独立滚动；
- 账户区域固定在底部。

选中态使用浅绿色表面和深绿色文字/图标，不使用紫色或大面积实色。

### 8.2 顶部工具栏

- 高度：`64px`；
- 显示助理状态、快捷链接、通知和用户头像；
- 只显示当前页面需要的全局操作；
- 与左侧导航顶部边界对齐；
- 不重复页面标题和页面级操作。

### 8.3 页面内容

标准内容页：

- 横向内边距：`32px`；
- 窄桌面：`24px`；
- 普通内容最大宽度：`1180px`；
- 数据表和编辑器可以使用全部可用宽度；
- 页面标题、描述和主操作使用共享 `PageHeader`。

### 8.4 响应式

| 宽度 | 行为 |
| --- | --- |
| `>= 1280px` | 完整侧边栏和标准内容边距 |
| `1024-1279px` | 默认收起侧边栏，隐藏最近任务列表 |
| `< 1024px` | 侧边栏改为抽屉，任务详情分栏可切换 |
| `< 768px` | 认证页单栏；普通管理页工具栏允许换行 |
| `< 480px` | 登录注册表单保持完整可用 |

AppDev IDE 在窄屏下将文件树和预览区改为可切换抽屉，不强行压缩三栏。

建议新增或收敛以下组件：

- `NewXAppShell`
- `WorkspaceSidebar`
- `TopUtilityBar`
- `PageHeader`
- `PageToolbar`
- `PageSection`
- `ObjectList`
- `ObjectCard`
- `DataTableShell`
- `StatusIndicator`
- `EmptyState`
- `ErrorState`
- `SettingsShell`

这些组件只负责视觉和结构，不读取业务数据。页面继续通过现有 hooks、store

## 10. 页面一致性矩阵

### 10.1 首页和新建任务

- 保留左侧导航、欢迎标题、任务输入和模板区域；
- 输入区适度收紧，避免无意义大留白；
- 模板使用行列表；
- 主操作为墨绿色；
- 模型、模式、附件、上下文和发送按钮沿用真实行为；
- 最近任务状态必须可识别。

### 10.2 任务详情

- 保留会话、执行步骤、产物、To-dos、输入区和右侧预览；
- 顶部 Token、导出、详情、收藏、分享和通知使用统一工具栏；
- 分栏拖拽和产物关闭行为不变；
- 消息内容和 Markdown 预览分别使用适合阅读的最大行宽；
- 错误状态不能再使用大面积浅红空白面板。

### 10.3 全部任务和任务中心

- 共享页面标题、筛选工具栏、搜索、状态筛选和批量操作；
- 使用表格或行列表，不使用任务卡片墙；
- 状态、收藏、更新时间和操作列统一；
- `任务中心`侧边菜单必须有图标；
- 空态、加载和失败状态使用共享组件。

### 10.4 资源库

- 保留类型筛选、状态筛选、搜索、新建和资源操作；
- 继续使用高密度表格/列表；
- 资源类型图标可以使用语义色，但尺寸和容器统一；
- 表头、行高、更多操作和分页使用共享规则。

### 10.5 技能管理

- 保留搜索、类型、状态、导入、AI 创建、手动创建和分页；
- Skill 是独立对象，可以保留三列卡片；
- 卡片使用白色表面和细边框，不使用绿色渐变背景；
- 内置、自定义、启用、停用使用统一标签和状态；
- 详情、更多操作和开关保持现有能力。

### 10.6 网页应用开发列表

- 保留发布筛选、搜索、刷新、导入和创建；
- 去掉页面级蓝灰渐变背景；
- 项目卡片使用全局白色表面、边框、状态标签和操作；
- 未发布、已发布、运行状态使用语义色；
- 项目标题、描述、创建者、时间和操作位置固定。

### 10.7 网页应用 IDE

- 保留文件树、编辑器、预览、控制台、保存、版本和发布能力；
- IDE 外壳使用全局导航、工具栏和边框；
- Monaco 内容区允许使用专业深色或浅色主题；
- 文件选中、未保存、运行中、错误和发布状态统一；
- 不修改现有 Provider、Sandbox 和安全边界。

### 10.8 工作空间

- 保留空间名称、成员、角色、邀请、搜索、筛选和分页；
- 去掉橙色头图标和紫色 Tab；
- 使用统一 `PageHeader`、Tab、提示条和成员表格；
- 个人空间只读说明和团队空间可编辑能力保持不变；
- 权限来自服务端真实角色，不因视觉重构改变。

### 10.9 账户设置、MCP 和 IM 机器人

- 保留左侧设置导航；
- Modal/Drawer 使用统一宽度、标题、分割线和关闭按钮；
- 表单项使用标准 `40px` 控件；
- 密钥字段继续遵循脱敏和浏览器自动填充安全规则；
- MCP 和飞书连接状态使用共享状态组件；
- 错误、重试、空态和权限提示不能只显示裸文本。

### 10.10 系统管理

- 保留独立 `/system` 路由和二级导航；
- 管理侧边栏使用相同 token，但允许更高信息密度；
- 用户、工作空间、模型、系统配置和 Sandbox 使用统一页面壳；
- 取消紫色选中态；
- `403`、加载失败和空数据使用共享反馈组件；
- 后端权限校验保持不变。

### 10.11 登录和注册

- 使用同一 NewX 三角品牌标识和墨绿色主色；
- 桌面可使用品牌说明加表单双栏；
- 移动端退化为单栏；
- 登录、注册、验证码、密码和错误提示保持原逻辑；
- 不使用通用 AI 渐变或无关插画。

## 11. 交互状态

所有交互组件必须覆盖：

- default
- hover
- active
- focus-visible
- disabled
- loading
- selected
- error

动效规则：

- hover/active：`120-160ms`；
- 菜单、Popover：`160ms`；
- Modal/Drawer：`200-240ms`；
- 页面首屏可使用一次轻量淡入，不为每个卡片增加重复动画；
- 遵循 `prefers-reduced-motion`。

## 12. 功能防跑偏规则

### 12.1 禁止改动

- 路由地址；
- 菜单名称、顺序和权限可见性；
- API 请求与响应合同；
- 服务端鉴权；
- 创建、编辑、删除、启停、发布和导出流程；
- 表格排序、筛选、分页和批量操作；
- 任务流式输出、产物预览、IDE 保存和 Sandbox 路由。

### 12.2 允许改动

- 组件组合和页面壳；
- CSS token 和 Less 组织；
- 图标和文案层级；
- 间距、圆角、边框、颜色和阴影；
- 不改变业务合同的交互反馈；
- 为可访问性补充 ARIA、焦点和键盘行为。

### 12.3 数据一致性

- 两处头像使用同一用户投影；
- 菜单状态使用同一路由事实；
- 权限状态使用服务端事实；
- 状态标签不能从展示文案反推业务状态；
- 视觉重构不引入页面本地 mock 数据。

## 13. 前端落地架构

建议结构：

```text
frontend/apps/coze-studio/src/
  styles/
    newx-tokens.less
    newx-foundations.less
    newx-motion.less
  components/
    newx-shell/
    newx-page/
    newx-feedback/
    newx-data-display/
```

落地策略：

1. 将 token 挂到应用根节点；
2. 用共享页面壳替代重复的标题、工具栏和内容宽度逻辑；
3. 收敛 `workspace-prototype.less` 中可共享规则；
4. 将 Workbench 和 AppDev 私有颜色、圆角、阴影替换为 token；
5. 页面迁移完成后删除无调用的兼容样式；
6. 不使用高权重全局选择器覆盖 Semi；
7. 优先通过现有组件 props 和主题变量定制。

重构期间允许短期页面适配层，但不能长期保留两套 token 或两个全局主题。

## 14. 验收矩阵

### 14.1 视觉验收

每类页面至少保留以下截图：

- `1440x1024` 完整桌面；
- `1280x800` 窄桌面；
- `1024x768` 收起导航；
- `390x844` 登录/注册移动端。

逐项检查：

- 页面标题和主操作位置；
- 左侧导航和顶部工具栏；
- 图标完整性；
- 两处头像一致性；
- 颜色、字体、圆角、控件高度和内容宽度；
- 表格、卡片、表单、弹窗、空态和错误态；
- 无内容裁切和横向溢出；
- 无控制台错误。

### 14.2 功能验收

- 空间切换和创建空间；
- 新建任务和流式输出；
- 任务列表、详情、产物和导出；
- 资源筛选、搜索、创建和操作；
