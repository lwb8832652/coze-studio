# Nuwax 技能管理完整对齐设计

## 1. 背景

当前 Coze Studio 已具备技能创建、导入、启停、删除、导出、试运行、版本快照、
资源编辑和版本回滚等基础能力，但技能管理仍以列表和侧边版本面板为主。Nuwax
已经形成从技能创建到文件开发、版本发布和跨空间复用的完整工作流。

本设计以 Nuwax 的用户可见行为和业务闭环为基准，在 Coze Studio 内进行原生
实现。不得直接复制 Nuwax 的 Umi、Ant Design 或 Java 代码，也不得以 UI
占位、内存数据或前端伪权限替代生产实现。

## 2. 目标

完成以下技能管理闭环：

1. 技能列表、搜索、筛选、分页和状态展示。
2. AI 辅助创建和手动创建两种入口。
3. `.skill`、`.zip`、`SKILL.md` 导入。
4. 技能元数据和完整文件项目编辑。
5. 文件新建、目录新建、重命名、删除、批量上传和保存。
6. 未保存修改保护和冲突处理。
7. 版本历史、快照查看、回滚和版本导出。
8. 试运行、执行状态、结果和错误展示。
9. 复制到其他工作空间、项目导出和删除。
10. 技能发布、发布状态和“有更新未发布”提示。
11. AI 创建任务与最终安装技能之间的来源关联。
12. 服务端空间权限、租户隔离和安全审计。

## 3. 范围边界

### 3.1 本次包含

- 当前工作空间内的技能管理和技能开发页面。
- 技能页面内的发布动作、发布版本和发布状态。
- 发布后技能的不可变快照及后续修改提示。
- 跨工作空间复制，但目标空间必须是当前用户有写权限的空间。
- AI 创建技能继续复用现有 `skill-creator`、任务运行和 `.skill` 安装能力。
- 手动创建对齐 Nuwax 的创建表单和创建后详情页。

### 3.2 本次不包含

- 公共技能市场的发现、推荐、收藏和订阅。
- 独立后台审核工作台及审核队列。
- 计费、订阅、积分和付费发布。
- 与技能管理无关的 Agent、工作流、MCP 或知识库重构。

如果发布到公共市场将来要求审核，应在独立规格中接入审核系统。本次发布语义
是“在当前工作空间形成可用的已发布版本”。

## 5. 信息架构和路由

### 5.1 技能管理页

保留：

`/space/:space_id/skill`

页面负责列表、搜索、筛选、分页、创建入口、导入以及卡片级操作。

### 5.2 标准技能详情页

新增：

`/space/:space_id/skill/:skill_id`

手动创建和导入成功后进入此页面。页面负责元数据、文件项目、版本历史、试运行、
发布和更多操作。

### 5.3 会话式技能开发页

新增：

`/space/:space_id/skill/:skill_id/conversation?thread_id=:thread_id`

通过 AI 创建并安装的技能记录来源任务。列表打开此类技能时进入会话式详情，
同时允许切换到标准文件工作台。若来源任务不存在或用户无权访问，降级到标准
详情页，不暴露任务内部数据。

### 5.4 AI 创建入口

保留：

`/space/:space_id/chats/new?mode=skill`

不得跳转到不带 `mode=skill` 的普通首页。该参数负责技能创建欢迎内容、预填
提示词、任务模板隐藏和 `.skill` 产物安装链路。

## 6. 技能管理页设计

### 6.1 页面头部

- 标题为“技能”。
- 主操作为“新建技能”。
- “新建技能”打开选择菜单，不增加中间创建页面。
- 菜单包含“AI 辅助创建”和“手动创建”。
- “导入技能”作为同级次要操作，不混入两种创建方式。

### 6.2 两种创建方式

AI 辅助创建：

- 进入当前空间的 `/chats/new?mode=skill`。
- 保留现有 `skill-creator` 提示词、任务执行、产物展示和安装能力。
- 安装成功后返回技能实体，并记录 `development_thread_id`。
- 用户可以从安装成功提示直接进入技能详情。

手动创建：

- 在技能管理页打开 Nuwax 对齐的表单弹窗。
- 字段包含图标、技能名称、使用场景和描述。
- 名称必填，使用场景必填，描述按后端合同校验。
- 提交期间防重复提交。
- 创建成功后关闭弹窗并进入新技能详情页。
- 创建失败保留用户输入并展示可操作错误。

### 6.3 搜索、筛选和分页

- 支持按名称和描述关键词搜索。
- 支持全部、未发布、已发布、有更新未发布、已停用状态筛选。
- 支持自定义技能、公共技能和内置技能类型筛选。
- 分页由服务端完成，默认按更新时间倒序。
- 搜索和筛选变化时回到第一页。
- URL 查询参数保存筛选状态，返回列表时可以恢复。

### 6.4 技能卡片

卡片至少展示图标、名称、描述、类型、使用场景、启用状态、发布状态和更新时间。
更多操作包含：

- 复制到工作空间。
- 导出项目。
- 删除。

内置技能和只读技能隐藏或禁用不允许的操作，并提供原因提示。删除必须二次确认。

## 7. 技能详情工作台设计

### 7.1 顶部区域

- 返回技能管理页。
- 展示图标、名称、启用状态和发布状态。
- 支持编辑元数据。
- 展示“已发布”或“有更新未发布”。
- 提供版本历史、试运行、发布和更多操作。
- 更多操作包含导入覆盖、导出项目和删除。

### 7.2 主工作区

采用三段式布局：

- 左侧：文件树和文件操作。
- 中间：文本或代码编辑器。
- 右侧：试运行面板；版本历史打开时替换为历史面板。

窄屏下右侧面板改为抽屉，中间编辑区保持可用。布局使用 Coze Design 和现有
Semi 能力，不直接引入 Ant Design。

### 7.3 文件树

支持：

- 选中文件和目录。
- 新建文件。
- 新建目录。
- 重命名。
- 删除。
- 批量上传。
- 刷新。

`SKILL.md` 是技能声明入口，不允许删除或重命名。路径必须是安全相对路径，
禁止 `..`、绝对路径、符号链接和重复规范化路径。

### 7.4 编辑器和保存

- 文本文件按扩展名设置语言模式。
- 二进制文件只展示元数据和下载操作。
- 修改后展示脏状态。
- 保存创建新的技能版本快照，不原地覆盖历史版本。
- 切换文件、切换版本、返回列表或关闭页面前检查未保存修改。
- 用户可以保存并继续、放弃修改或取消离开。
- 保存冲突返回当前版本信息，禁止静默覆盖其他会话的更新。

### 7.5 批量上传和导入覆盖

- 单文件和总大小限制由前后端共同校验。
- 上传前展示冲突文件清单。
- 用户明确确认后才允许覆盖同路径文件。
- 导入 `.skill` 或 `.zip` 时先解析和验证，再原子替换当前草稿。
- 任一文件失败时不留下半成品版本。

## 8. 版本和发布

### 8.1 草稿与发布状态

技能状态分为：

- `draft`：从未发布。
- `published`：当前草稿与最近发布版本一致。
- `changed`：最近发布后又发生修改。
- `disabled`：技能被停用；发布状态仍保留。

发布状态与启用状态是两个独立维度。

### 8.2 版本历史

- 每次保存、导入覆盖、回滚和发布均创建不可变版本快照。
- 历史列表按创建时间倒序。
- 可以查看 `SKILL.md` 和资源文件。
- 可以导出指定版本。
- 回滚会以目标历史版本为基础创建新快照，不修改旧记录。

### 8.3 发布

- 发布前执行声明解析、必填字段、路径、资源大小、权限和执行配置校验。
- 发布创建不可变发布记录并更新技能的最近发布版本。
- 发布成功后列表和详情立即刷新。
- 发布失败不改变当前草稿和已有发布版本。
- 发布操作必须记录操作者、空间、技能、版本、时间和结果。

## 9. 试运行

- 详情页右侧提供输入编辑区和运行按钮。
- 运行使用当前已保存草稿版本，不使用浏览器内未保存内容。
- 运行中展示状态并禁止重复提交。
- 成功展示安全裁剪后的输出和关联任务编号。
- 失败展示用户可理解的错误，不暴露 prompt、工具参数、凭据或 provider 原始
  响应。
- 用户离开页面不强制取消已经提交的后端任务。

## 10. 后端领域和数据合同

### 10.1 技能元数据扩展

在现有 `skills` 记录上增加或等价投影：

- `icon_uri`：技能图标引用。
- `usage_scenarios`：受控枚举列表。
- `development_thread_id`：可空的 AI 创建来源任务。
- `published_version_id`：可空的最近发布版本。
- `published_at`：最近发布时间。
- `revision`：乐观锁版本。

不保存外部可控绝对文件路径。图标和文件使用受控对象引用或数据库内容。

### 10.2 列表合同

扩展 `ListSkillsRequest`：

- `keyword`。
- `type`。
- `enabled`。
- `publish_status`。
- `page`。
- `page_size`。

响应增加总数和分页信息。所有过滤必须绑定经过鉴权的当前空间。

### 10.3 文件合同

新增等价 API：

- 获取当前草稿文件树。
- 获取单个文件内容。
- 新建文件或目录。
- 保存文件。
- 重命名文件或目录。
- 删除文件或目录。
- 批量上传文件。

写操作携带 `revision` 或基线版本 ID，冲突返回 `409`。每个操作都由服务端
校验技能归属空间和当前用户写权限。

### 10.4 空间和发布合同

新增等价 API：

- 复制技能到目标空间。
- 发布当前草稿。

复制必须生成新的技能 ID、版本 ID 和资源 ID，不共享可变记录。目标空间权限
检查发生在任何写入之前。

### 10.5 安装来源关联

扩展现有 `InstallSkillFromArtifact`：安装成功时将已鉴权的 `thread_id` 写入
`development_thread_id`。不得信任客户端提交的任意用户或空间字段。

## 11. 迁移和兼容

- 新字段使用兼容默认值，已有技能不需要数据回填才能读取。
- 旧技能首次打开详情时从最近版本快照构建草稿文件树。
- 没有发布记录的已有技能显示为“未发布”。
- 现有技能列表、Agent Runtime 技能装载和 `.skill` 导入接口保持兼容。
- Atlas 迁移只负责结构变更，不在迁移脚本中执行大规模业务数据转换。
- 迁移需通过 Atlas `v0.35.0` hash 和 validate。

## 12. 权限和安全

- 读取、编辑、删除、复制、发布、导入、导出和试运行均使用服务端认证上下文。
- 客户端的 `space_id` 只用于定位，不能作为授权事实。
- 列表和详情必须防止跨空间枚举技能 ID。
- 内置技能默认只读，除非领域规则明确允许空间级启停。
- 文件内容、文件名、压缩包和图标均执行大小、类型和路径校验。
- 导出内容不得包含凭据、对象存储内部地址或隐藏运行配置。
- 审计只保存受控元数据，不保存原始技能执行输入输出。

## 13. 前端状态要求

每个页面和操作覆盖：

- loading。
- empty。
- error。
- disabled。
- readonly。
- refresh。
- permission denied。
- conflict。

所有异步按钮需要 loading 和重复提交保护。错误后保留用户可恢复的输入和当前
编辑上下文。

## 14. 实施顺序

### 14.1 管理闭环

- 扩展元数据和列表合同。
- 完成搜索、筛选、分页和卡片。
- 完成两种创建、导入、复制、导出和删除。
- 创建成功和导入成功进入标准详情页。

### 14.2 开发闭环

- 完成详情路由和工作台布局。
- 完成草稿文件树和文件 CRUD。
- 完成上传、保存、冲突和离开保护。
- 将现有版本能力整合到详情页。

### 14.3 交付闭环

- 完成试运行和发布状态。
- 完成会话式技能详情和来源任务关联。
- 完成权限、审计、安全边界和兼容迁移。
- 完成自动化测试和内置浏览器对照验收。

三个闭环在同一功能主线连续实施，但每个闭环都必须通过相应测试后才能进入下
一个闭环。

## 15. 测试策略

### 15.1 后端

- 领域测试：路径安全、文件 CRUD、快照、回滚、复制、发布和状态计算。
- 应用测试：鉴权前置、跨空间拒绝、乐观锁冲突、原子导入和失败回滚。
- Handler 和路由测试：参数、HTTP 状态、错误脱敏和响应合同。
- Repository 测试：租户隔离、分页、搜索、软删除和发布版本关联。

### 15.2 前端

- 列表筛选、分页和 URL 状态测试。
- 创建方式选择和手动创建表单测试。
- 导入校验、复制和删除测试。
- 文件树 CRUD、上传、保存、脏状态和离开保护测试。
- 版本、回滚、试运行和发布状态测试。
- 权限、只读、错误、冲突和重试测试。

### 15.3 页面验收

默认使用 Codex in-app browser，对 Nuwax 和 Coze 执行相同流程：

1. 打开技能管理列表并验证筛选、搜索和分页。
2. 分别用 AI 和手动方式创建技能。
3. 导入 `.skill`、编辑文件、新建目录、上传、重命名和删除。
4. 保存并验证版本历史和“有更新未发布”。
5. 试运行并检查成功与失败状态。
6. 发布、回滚、导出和复制到其他空间。
7. 验证只读用户、无权限空间和跨空间 ID 访问失败。
8. 检查页面控制台无未处理错误。

验收记录必须包含 URL、账号、空间、关键交互结果、接口结果和截图。

## 16. 完成标准

只有同时满足以下条件才能声明完整对齐：

- 本设计包含的用户流程均可使用真实后端数据完成。
- 页面结构、关键文案、操作顺序、状态反馈和 Nuwax 对齐。
- 不存在仅前端可见但后端未授权的操作。
- 不存在内存 stub、硬编码 Owner 或伪造发布状态。
- 目标前后端测试通过。
- Atlas 校验通过。
- Coze 和 Nuwax 同流程的 in-app browser 对照验收通过。
- 已知差异和范围外能力均有明确记录。
