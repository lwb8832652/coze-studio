# TD-SKILL-003 Skill Creator Entry

## DeerFlow Source Confirmed

- `frontend/src/components/workspace/settings/skill-settings-page.tsx`
  - `新建技能` calls `router.push("/workspace/chats/new?mode=skill")`.
- `frontend/src/components/workspace/welcome.tsx`
  - `mode=skill` renders the skill-creator welcome title and description.
- `frontend/src/components/workspace/input-box.tsx`
  - `mode=skill` hides normal suggestions and preloads the skill creator prompt.
- `frontend/src/core/skills/api.ts`
  - `.skill` install calls `POST /api/skills/install` with `thread_id` and
    artifact `path`.
- `frontend/src/components/workspace/artifacts/artifact-file-list.tsx`
  - `.skill` artifacts show an install action next to download.
  - The action is rendered whenever the file ends with `.skill`; DeerFlow does
    not check whether the skill is already installed before showing the
    button. It only disables the button while the install request is in
    progress.
- `frontend/src/components/workspace/artifacts/artifact-file-detail.tsx`
  - `.skill` artifact details also expose the same install action.
  - The detail action follows the same rule: show install for `.skill`, disable
    only while installing/static-site mode.
- `backend/packages/harness/deerflow/skills/installer.py`
  - Duplicate installation is rejected by `SkillAlreadyExistsError`.
- `backend/tests/test_client_e2e.py`
  - `test_install_skill_duplicate_rejected` confirms installing the same
    archive twice raises an `already exists` error.
- `backend/app/gateway/routers/skills.py`
  - `POST /api/skills/install` resolves the generated artifact path, imports
    the skill archive, and returns `{ success, skill_name, message }`.
- DeerFlow Settings Skills does not expose a separate version/resource/export
  management page. Custom read/edit/history/rollback exist at the API level,
  but the visible settings mainline is list, enable switch, create entry, and
  generated `.skill` install.

## Coze Changes

- `frontend/apps/coze-studio/src/pages/skill/index.tsx`
  - `新建技能` and empty-state `创建你的第一个技能` now navigate to
    `/space/:space_id/chats/new?mode=skill`.
  - Removed the settings-page local create/import panel entry points from the
    DeerFlow-aligned page surface.
- `frontend/apps/coze-studio/src/pages/workbench/index.tsx`
  - Reads `mode=skill`.
  - Renders DeerFlow skill-creator title and description.
  - Prefills the composer with the DeerFlow skill-creator prompt.
  - The prompt now explicitly asks the agent to create an installable `.skill`
    package with `create_skill_package` and `present_files`, then tells the
    user that clicking install will place it under custom skills.
  - Hides the normal template section in skill creation mode.
- `backend/api/handler/coze/workbench_skill_service.go`
  - Adds Workbench adapter `POST /api/workbench/skills/install`.
  - Reads the generated artifact through the task artifact content boundary,
    validates `.skill`, and imports through the existing Skill application
    service.
  - Response keeps the DeerFlow-compatible data shape:
    `{ success, skill_name, message }`.
- `frontend/apps/coze-studio/src/pages/tasks/service.ts`
  - Adds `installSkillFromArtifact({ space_id, thread_id, artifact_id })`.
- `frontend/apps/coze-studio/src/pages/tasks/task-artifact-actions.ts`
  - Adds `install_skill` artifact action mode.
- `frontend/apps/coze-studio/src/pages/tasks/task-artifact-message-list.tsx`
  and `task-artifact-list-item.tsx`
  - `.skill` artifacts show `安装` beside `下载`, using the same action hook as
    preview/download.
  - The install action intentionally remains visible after successful or
    duplicate installs, matching DeerFlow's artifact UI. Duplicate clicks
    surface the backend duplicate error instead of switching the artifact card
    to a Coze-specific `已安装` state.
- `backend/domain/skill/service/declaration.go`
  - Adds parser-level default-type override support.
  - Existing builtin sync keeps missing frontmatter `type` as `deer_skill`.
  - User import/install paths now default missing frontmatter `type` to
    `custom_skill`, matching DeerFlow custom skill installation behavior.
- `backend/application/skill/skill.go`
  - Workbench import/install goes through the custom default type path, so
    `.skill` packages generated by skill-creator appear in the custom list
    after installation.
- `backend/application/agentthread/adk_artifact_tools.go` and
  `artifact_output.go`
  - Adds `create_skill_package`, a bounded ADK runtime tool that accepts
    structured `skill_name`, `skill_md`, and optional text resources, then
    creates a real zip `.skill` output file under `/mnt/user-data/outputs`.
  - The tool does not execute shell commands or accept arbitrary output
    locations. Resource paths must be safe relative paths and the generated
    file still requires `present_files` before users can install it.
- `frontend/apps/coze-studio/src/pages/skill/skill-version-panel.tsx` and
  `skill-version-panel-hooks.ts`
  - Keep Coze's extended version/resource/export management in the secondary
    panel rather than the DeerFlow-style Skills list main surface.
  - Version export rebuilds an installable `.skill` archive from the selected
    `SKILL.md` snapshot plus stored resources, so generated/custom skills can
    be round-tripped without losing bundled text resources.

## Remaining Under TD-SKILL-003

  produces a `.skill` archive in the local test workspace.
- Complete DeerFlow skill-creator bundled-resource parity. Current Eino runtime
  can create `.skill` archives through `create_skill_package`, but still loads
  only `SKILL.md` instructions into the model. DeerFlow's original
  skill-creator also ships scripts, references, agents, eval viewer assets, and
  additional packaging/evaluation helpers that are not yet executable through
  the Coze runtime.
