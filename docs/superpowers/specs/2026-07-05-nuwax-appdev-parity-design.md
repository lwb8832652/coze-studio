# Coze Studio 二期：nuwax-ai 网页应用开发迁移设计

## 1. 结论

二期主线从“系统管理完全对齐”切换为“网页应用开发 AppDev 完整迁移”。
系统管理、用户管理、模型配置等后台页面保留当前一期基础能力，完整样式与
功能对齐顺延到三期。

二期将在当前 Coze Studio 左侧一级菜单新增 `网页应用开发`，位置放在
`资源配置` 下方、`技能配置` 上方。该菜单承载 nuwax-ai 的 AppDev Web IDE
能力，目标是让用户在当前项目内完成网页应用的创建、AI 辅助开发、文件编辑、
实时预览、开发环境管理和导出发布闭环。

## 3. 一期完成边界

一期按当前决策视为可以收口，完成边界如下：

- `工作空间` 菜单入口保留在左侧一级菜单中，位置在 `全部任务` 上方。
- 账号设置和退出登录保留在左下角头像菜单中。
- 系统管理入口保留在左下角头像菜单中，仅系统管理员可见。
- 系统管理已有基础用户、工作空间、模型配置、设置能力，但不追求一期完全对齐。

三期再继续处理：

- 系统管理页面视觉、交互、字段和权限与 nuwax-ai 完整对齐。
- 用户管理、模型配置、系统设置、工作空间管理的生产级细节补齐。
- 后台内容管理、发布管理等 nuwax-ai 后台能力是否迁移另行评估。

## 4. 二期目标

二期目标是迁移 nuwax-ai 的 `网页应用开发` 能力，而不是只增加菜单壳。
本期 AppDev 交付标准是生产级完整对齐：页面、交互、接口、状态、权限、安全、
错误处理、数据持久化和验收用例都必须闭环。除非用户重新调整范围，否则不把
AppDev 的可见功能细节留到三期或后续补丁中。

用户应该可以完成以下核心流程：

1. 从左侧一级菜单点击 `网页应用开发`。
2. 进入网页应用项目列表或创建入口。
3. 新建网页应用项目，填写应用名称和初始需求。
4. 进入 AppDev Web IDE 详情页。
5. 通过 AI 对话生成或修改网页应用。
6. 查看 AI 思考、工具调用、执行状态和结果。
7. 查看项目文件树，打开文件并编辑代码。
8. 保存、新增、删除、重命名文件。
9. 启动或重启开发环境。
10. 在内嵌预览区实时查看网页应用。
11. 查看开发日志和错误状态。
12. 导出项目产物，后续扩展到发布。

## 4.1 生产级交付硬标准

二期 AppDev 只有在以下条件全部满足后才能标记完成：

- 功能对齐：nuwax-ai AppDev 参照页中用户可见的入口、主流程、按钮、菜单、
  弹窗、消息类型、状态提示、编辑器、预览区、开发日志和错误恢复都完成迁移。
- 视觉对齐：页面布局、信息层级、间距、状态样式、空态、错误态、loading、
  disabled、hover、selected、运行中和异常态都要逐项对照。
- 数据闭环：项目、文件、会话、运行状态、模型选择、数据源绑定、日志和导出
  不能只存在前端内存中，刷新页面后关键状态必须可恢复。
- 权限闭环：所有接口按当前登录用户和空间校验权限，不能信任前端传入的
  `user_id`、`space_id`、owner 或文件路径。
- 安全闭环：文件路径、预览地址、日志、SSE 事件、AI 工具调用摘要和导出产物
  都必须脱敏和边界检查，不能暴露凭据、内部 checkpoint、raw prompt、raw
  provider body 或宿主敏感路径。
- 运行闭环：开发环境启动、保活、重启、停止、异常恢复和日志查询必须可用，
  不能只展示静态状态。
- 兼容闭环：AppDev 页面懒加载，不能影响任务页、工作空间页和系统管理页首屏。
- 验收闭环：每个用户路径都要有对应验证记录；发现差异必须修完后再确认完成。

阶段拆分只用于降低实施风险，不代表阶段性交付可以缺功能。二期最终交付前，
不接受“页面已搭好、接口后补”“功能可用、样式后补”“样式接近、状态后补”
这类遗留。

- 支持新建项目。
- 支持导入项目压缩包。

首版字段：

- 创建者

### 6.2 IDE 主界面

- 左侧：AI 对话区。
- 中间：文件树和 Monaco 编辑器。
- 右侧：实时预览、开发日志、运行状态。

nuwax-ai 后端是独立实现，Coze Studio 后端是 Go + Hertz。二期不直接依赖
nuwax Java 后端作为长期方案，而是在 Coze 后端实现等价 AppDev API 和领域
模型。

运行环境 API：

### 7.2 数据模型

建议新增领域模型：

- `AppDevProject`
  - 项目 ID、空间 ID、名称、描述、创建者、状态、运行状态、预览 URL、创建时间、
    更新时间。
- `AppDevFile`
  - 项目 ID、路径、类型、大小、内容版本、更新时间。
- `AppDevConversation`
  - 项目 ID、会话 ID、请求 ID、状态、创建时间、结束时间。
- `AppDevMessage`
  - 会话 ID、消息类型、展示内容、工具调用摘要、排序序号。
- `AppDevRuntime`
  - 项目 ID、开发服务器状态、端口、URL、最后保活时间、错误摘要。

文件内容存储不建议长期只放数据库。实现时优先评估仓库已有对象存储、
artifact、workspace 文件存储能力；如果一期先落本地开发目录，需要封装在
infra 层，避免业务层依赖本地路径。

### 7.3 权限和租户隔离

所有 AppDev API 必须从服务端认证上下文读取用户和空间，不信任前端传入的
`user_id`、`space_id`、owner 等字段。

最低权限要求：

- 用户必须属于当前空间。
- 普通成员是否可访问受 `allow_develop` 和空间角色控制。
- 项目列表只返回当前空间内项目。
- 文件路径必须做规范化，禁止 `../` 越权。
- 预览 URL、日志、构建输出必须脱敏。
- SSE 事件不能暴露 raw prompt、隐藏配置、凭据和内部 checkpoint。

## 11. 风险和处理策略

### 11.1 运行环境安全风险

网页应用开发会运行用户生成代码，必须限制运行目录、网络、文件访问和资源占用。
二期实现时需要先给运行环境加最小沙箱边界，不能让预览服务直接访问宿主敏感
文件。

### 11.2 nuwax-ai 与 Coze 技术栈差异

nuwax-ai 使用自己的前端和后端服务结构，Coze Studio 使用 React + TypeScript
+ Go + Hertz。前端可以迁移交互与组件结构，后端必须按 Coze 分层重建，不建议
长期以代理 nuwax 后端作为正式交付。

### 11.3 Monaco 和预览带来的构建体积

Monaco Editor 体积较大，AppDev 页面必须懒加载，不能影响普通任务页面首屏。

### 11.4 SSE 事件契约

nuwax-ai 的 SSE 事件较丰富。二期需要先定义稳定事件投影，前端只消费审核后的
bounded metadata，不展示 raw provider body、prompt、credentials 或内部
checkpoint。

## 12. 二期验收结论（2026-07-10）

二期 AppDev 已按本设计完成生产验收，不再处于“页面骨架”或“接口待接入”状态：

1. 菜单和路由已接入，并使用 `React.lazy` 隔离 AppDev 资源。
2. 项目、文件、运行时、预览、日志、AI 对话、原型图、模型、数据源、快照、
   导入导出和构建发布均使用真实后端数据与本地持久化目录。
3. 服务端会话和工作空间成员校验覆盖全部 AppDev handler；未登录请求返回 401，
   非空间成员返回权限错误码 `700000007`。
4. 文件路径、压缩包、SSE 展示字段和原型图输入均有边界检查与自动化覆盖。
5. AI 长任务在 SSE 结束事件丢失时会通过后端状态对账自动恢复，不需要刷新页面。
6. 内置浏览器已对照本地 nuwax 页面验收项目入口和 IDE，并回归任务、工作空间、
