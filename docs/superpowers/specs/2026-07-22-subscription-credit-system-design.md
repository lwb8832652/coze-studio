## 1. 背景与结论

本专题把 Nuwax 的“订阅与积分”能力完整引入 Coze Studio。该能力不是一组
后台表格，而是由账户、积分账本、订阅权益、商品目录、业务订单、运行时计
量、用户页面和运营审计组成的商业闭环。

完整方案采用以下结论：

1. 先建设不可变积分账本，再接入后台页面和运行时扣费。
2. 订阅计划、积分套餐和订单必须保存版本或快照，历史记录不能随配置变化。
3. 所有加减积分、订阅激活、订单回调和周期重置必须幂等。
4. 模型调用使用“预占、结算、释放”流程，不能只在调用结束后直接减余额。
5. 后台入口按 Nuwax 的“订阅与积分”二级菜单组织，视觉语言使用 Coze 当前
   统一后的 C 端设计系统。
6. C 端提供我的订阅、积分余额与明细、积分增购、我的订单和用量统计。
7. 支付渠道通过 `PaymentGateway` 端口接入，订阅领域不绑定具体厂商。
8. Nuwax 独立的“支付与收益”菜单不在本专题范围，包括商户入驻、创作者分
   成、提现和结算。

### 2.2 Nuwax 已核实的业务规则

1. 积分按批次管理，可分别设置来源和过期时间。
2. 扣减时优先使用即将过期的批次。
3. 积分来源至少包含订阅、增购、活动、人工发放和透支借款。
4. 消费类型至少包含模型、智能体、工具和人工扣减。
5. 增加和扣减使用业务单号防止重复处理。
6. 扣减余额使用乐观锁处理并发冲突。
7. 订阅包含开始时间、结束时间、周期、调用次数和下次重置时间。
8. 周期重置会清零周期调用次数并发放订阅积分。
9. 订单保存商品项快照，支付成功后再发放积分或激活订阅。
10. 模型定价按上下文区间维护输入、输出和缓存 Token 单价。

### 2.3 Coze 当前差异

Coze 当前已经持久化任务级 Token 用量和 `CostMicros`，也有运行时调用次数、
失败次数和耗时的 Prometheus 指标，但缺少以下生产合同：

- 不可变积分账本和积分批次。
- 余额预占、结算与释放。
- 订阅计划、订阅快照、权益和周期重置。
- 积分套餐、业务订单和支付回调状态机。
- 单次模型调用审计、缓存 Token 和定价快照。
- 管理员订阅积分 API 与 C 端账户 API。
- 运行时余额不足拦截和幂等扣费。

因此不得把当前 `CostMicros` 直接当作积分余额，也不得用前端本地状态模拟订
阅或积分。

- 商户入驻和支付商户资料管理。
- 创作者或开发者收益分成。
- 提现申请、提现审核、打款和结算。
- Nuwax“支付与收益”菜单下的其它能力。
- 工作空间对公账户、发票和企业采购。
- 多币种结算。

### 3.3 支付边界

本专题包含完整订单状态机、支付尝试记录、回调验签端口和支付适配器合同。
真实支付厂商不是订阅领域的一部分，必须通过 `PaymentGateway` 实现。

未配置生产支付适配器时：

- 免费订阅、管理员发放和运行时扣费仍可正常工作。
- 付费套餐可以展示，但购买按钮必须显示不可用原因。
- 服务端创建付费支付会话必须 fail closed，不能伪造成功订单。
- debug 环境可提供显式标记的测试适配器，但生产构建不得启用。

## 4. 领域模型

### 4.1 计费主体

账本使用统一 `BillingSubject`：

| 字段 | 说明 |
| --- | --- |
| `subject_type` | `USER` 或预留的 `SPACE` |
| `subject_id` | 用户 ID 或空间 ID |
| `tenant_id` | 租户隔离键 |
| `currency` | 积分账户固定为 `CREDIT` |

本次 Nuwax 对齐只启用 `USER`。团队空间内的调用按实际发起用户计费。 schema
预留 `SPACE`，但不在本期开放工作空间共享余额，避免后续改表。

### 4.2 数值精度

- 积分使用 `credit_micros BIGINT`，一积分等于 `1_000_000` 微积分。
- 金额使用 `money_micros BIGINT` 和 ISO 币种代码，首期只允许 `CNY`。
- Token 数量使用 `BIGINT`。
- 前后端不得使用二进制浮点执行结算。
- 页面展示时统一格式化，数据库和 API 始终传整数或十进制字符串。

### 4.3 核心表

| 表 | 作用 | 关键约束 |
| --- | --- | --- |
| `billing_config` | 租户级开关和兑换配置 | 每租户唯一、版本号、审计字段 |
| `billing_account` | 计费主体账户 | 主体和币种唯一、余额版本号 |
| `credit_grant_batch` | 可消费积分批次 | 来源、总额、剩余、过期时间、版本号 |
| `credit_ledger_entry` | 不可变积分流水 | 只追加、幂等键唯一、关联批次和业务对象 |
| `credit_reservation` | 运行时余额预占 | 预占、已结算、已释放、过期状态 |
| `subscription_plan` | 订阅计划目录 | 状态、排序、当前版本 |
| `subscription_plan_version` | 计划不可变版本 | 价格、周期、权益和赠送积分快照 |
| `user_subscription` | 用户订阅实例 | 当前状态、周期和下次重置时间 |
| `subscription_period` | 周期执行记录 | 重置和赠送积分幂等 |
| `credit_package` | 积分商品目录 | 状态、排序、当前版本 |
| `credit_package_version` | 积分商品快照 | 积分、售价、有效期 |
| `billing_order` | 业务订单 | 状态机、用户、金额、幂等键 |
| `billing_order_item` | 订单商品项 | 商品类型、商品版本和完整快照 |
| `payment_attempt` | 支付尝试 | 渠道、外部单号、状态、验签结果 |
| `model_price_tier` | 模型价格区间 | 模型、上下文上限和版本唯一 |
| `model_invocation_record` | 单次模型调用审计 | 状态、Token、价格快照、费用和关联任务 |
| `billing_outbox` | 可靠领域事件 | 事务内写入、异步投递、重试和死信 |

所有业务表必须包含租户隔离键、创建时间、更新时间和必要的操作者字段。账本
流水、订单项快照和模型调用价格快照禁止原地修改。

### 4.4 积分类型

发放来源：

`SUBSCRIPTION`、`PURCHASE`、`ACTIVITY`、`MANUAL`、`SIGNUP_GIFT`、
`DAILY_GIFT`、`REFUND`。

消费来源：

`MODEL_CALL`、`AGENT_CALL`、`TOOL_CALL`、`MANUAL_DEDUCT`、
`ADJUSTMENT`。

每条流水同时记录来源类型、操作类型、业务对象、操作者、业务单号和安全审
核后的备注。用户可见备注与内部审计备注分离。

## 5. 状态机与事务

### 5.1 积分发放

1. 校验租户、主体、来源、金额和过期时间。
2. 使用 `(tenant_id, idempotency_key)` 查询已有结果。
3. 锁定或创建积分账户。
4. 创建积分批次。
5. 追加增加流水并更新账户投影余额。
6. 事务内写入 outbox 事件。
7. 重试请求返回原结果，不重复发放。

### 5.2 积分扣减

1. 按有效期升序加载可用批次，永不过期批次排在最后。
2. 在事务内校验总可用余额。
3. 使用批次版本号逐批扣减。
4. 每个命中批次追加一条明细流水，共用同一事务业务单号。
5. 更新账户投影余额并写入 outbox。
6. 乐观锁冲突返回可重试错误，不允许部分提交。

默认不允许透支。只有显式内部策略和专用权限可启用透支，前端人工扣减不暴
露该开关。

### 5.3 预占与结算

长耗时任务采用三阶段流程：

1. `Reserve`：按模型价格和请求上限估算最大费用并预占余额。
2. `Settle`：收到真实用量后按价格快照结算实际费用。
3. `Release`：释放未使用预占；调用未开始或取消时释放全部。

预占记录必须有过期时间。补偿任务会释放已过期但未结算的预占，并生成审计
事件。相同调用 ID 的结算只能成功一次。

### 5.4 订阅生命周期

状态为 `PENDING`、`ACTIVE`、`CANCEL_AT_PERIOD_END`、`EXPIRED`、
`CANCELLED`。

1. 免费计划可以直接激活。
2. 付费计划只有对应订单支付成功后才能激活。
3. 激活时复制计划版本、价格和权益快照。
4. 周期任务使用订阅 ID 和周期开始时间作为幂等键。
5. 周期重置调用次数并发放订阅积分。
6. 过期任务只推进状态，不删除历史记录。
7. 计划下架不影响已激活订阅的当前周期权益。

升级、降级和自动续费在首期按“下个周期生效”实现，避免周期中途进行复杂差
额结算。永久计划没有结束时间和周期重置，除非计划明确配置月度赠送权益。

### 5.5 订单生命周期

状态为 `PENDING`、`PAYING`、`PAID`、`FAILED`、`CANCELLED`、`CLOSED`、
`REFUNDED`。

1. 创建订单时保存商品版本和展示快照。
2. 同一购买意图通过幂等键复用未完成订单。
3. 服务端根据商品快照计算金额，不接受客户端金额。
4. 支付回调先验签，再按外部交易号和事件号去重。
5. 状态推进和权益发放在同一事务或可靠 outbox 流程中完成。
6. 重复回调不得重复激活订阅或发放积分。
7. 退款必须追加冲正流水，不删除原积分流水。

## 6. 模型定价与运行时扣费

### 6.1 定价合同

每个模型可配置多级上下文价格：

- 上下文上限。
- 输入 Token 单价。
- 缓存输入 Token 单价。
- 输出 Token 单价。
- 币种和计价单位。
- 生效时间和版本。
- 计费启用状态。

单次调用按调用开始时的有效价格版本生成价格快照。后续修改价格不能改变历
史费用。

### 6.2 调用审计

`model_invocation_record` 至少记录：

- 租户、用户、空间、任务、线程和调用 ID。
- 模型配置 ID、供应商、模型标识和价格版本。
- 调用状态、开始时间、结束时间和安全错误码。
- 输入 Token、缓存输入 Token、输出 Token 和总 Token。
- 金额、积分、兑换比例快照和结算状态。
- 预占 ID、账本事务 ID 和重试序号。

不得记录 prompt、completion、密钥、工具参数、工具结果或供应商原始响应。

### 6.3 计费策略

- 有真实 Token 用量时按真实用量结算，不以调用成功与否作为唯一条件。
- 供应商未返回用量时不猜测扣费，记录 `UNMETERED` 并进入运营告警。
- 免费调用额度先消耗权益次数，资源费用是否另计由 `function_only` 决定。
- 总开关关闭时继续记录影子用量，但不预占或扣减积分。
- 余额不足时在调用前返回稳定业务错误，不启动模型调用。
- 已开始调用但结算金额超过预占时，允许在配置上限内追加结算；超限进入人
  工对账，不能把账户静默扣成负数。

- `/account/billing/orders`
- `/account/billing/usage`

默认落在订阅概览。页面共享当前项目统一的顶部账号组件、默认头像、通知组件
和 C 端内容宽度，不新增一级业务菜单。

### 8.3 页面状态

所有页面必须覆盖：

- 首次加载骨架。
- 空态和引导动作。
- 请求失败与重试。
- 无权限状态。
- 功能总开关关闭状态。
- 支付适配器未配置状态。
- 保存、发放、扣减和支付处理中状态。
- 禁用、只读和危险操作二次确认。
- 游标分页、筛选重置和刷新。

人工扣减、计划下架、套餐删除和取消订单使用明确的影响说明，不能只显示通用
“确定删除吗”。

## 9. 权限、安全与隐私

| 操作 | 权限 |
| --- | --- |
| 系统配置和套餐管理 | 系统管理员 |
| 用户积分查询 | 系统管理员 |
| 人工发放和扣减 | 系统管理员并写审计 |
| 查看个人余额、订阅和订单 | 当前认证用户 |
| 运行时预占和结算 | 内部服务身份 |
| 支付回调 | 验签通过的渠道适配器 |

安全要求：

- 服务端不信任客户端用户 ID、金额、价格、余额和权益。
- 支付密钥通过现有加密配置机制保存，不回显、不写日志。
- 支付回调保留摘要和安全元数据，不保存未经审核的原始敏感报文。
- 管理员备注和用户可见备注分离。
- 账本、订单和订阅读取都必须带租户条件。
- 对导出和大范围查询设置限制并记录审计。
- Workbench API/UI 不暴露供应商原始用量、隐藏运行配置或内部定价规则之外
  的敏感字段。

## 10. 一致性、补偿与对账

1. 核心余额更新、批次扣减、账本流水和 outbox 必须处于同一数据库事务。
2. 外部支付和内部权益使用最终一致性，通过 outbox 驱动。
3. 每个异步消费者使用事件 ID 和业务幂等键去重。
4. 定时任务扫描超时预占、支付中订单、未重置订阅和未结算调用。
5. 对账任务比较模型调用费用、积分账本和账户投影余额。
6. 投影余额可从账本重建；发现不一致时冻结自动修正并生成管理员告警。
7. 补偿只能追加冲正记录，不能修改或删除历史流水。

## 11. 可观测性

至少提供以下指标：

- 预占成功、失败和余额不足次数。
- 结算成功、失败、重复和超预占次数。
- 积分发放、扣减、冲正和过期金额。
- 订单各状态数量和支付回调失败次数。
- 订阅激活、过期和周期重置数量。
- 未计量模型调用数量。
- 对账不一致数量和补偿任务积压。

日志必须使用订单 ID、调用 ID、账本事务 ID 等内部关联标识，禁止输出支付密
钥、模型密钥、prompt 和原始支付报文。

## 12. 灰度与上线

### 阶段 A：账本内核

- 建表并实现账户、批次、流水、预占和幂等事务。
- 仅开放管理员测试 API。
- 不接入运行时扣费。

### 阶段 B：目录与后台

- 实现基础配置、订阅计划、积分套餐、用户积分和订单页面。
- 开启管理员人工发放与扣减。
- 保持总开关关闭。

### 阶段 C：C 端账户

- 实现我的订阅、积分、订单和用量页面。
- 开放免费计划和赠送积分。
- 付费按钮受支付适配器能力控制。

### 阶段 D：影子计量

- 记录模型单次调用、定价快照和预计积分。
- 不实际扣减，对比现有 Token 聚合数据。
- 影子数据连续对账通过后才能进入下一阶段。

### 阶段 E：强制计费

- 开启预占、结算和余额不足拦截。
- 先对内部测试用户灰度，再逐步扩大。
- 回滚只关闭强制扣费，保留调用审计、账本和订单历史。

### 阶段 F：生产支付

- 接入已选定并完成安全评审的支付适配器。
- 验收回调验签、重复回调、超时、失败、取消和退款。
- 未完成生产适配器验收前，不开放真实付费购买。

## 13. 验收标准

### 13.1 账本与并发

- 相同幂等键重复发放只产生一次余额变化。
- 相同调用重复结算只产生一次消费。
- 并发扣减不能出现负余额或丢失更新。
- 多批次扣减顺序符合“先过期先使用”。
- 事务失败不会留下部分批次扣减。
- 账本汇总可重建账户余额。

### 13.2 订阅

- 免费计划可正确激活。
- 付费计划不能在支付成功前激活。
- 下架计划不改变已生效周期权益。
- 周期重置重复执行不重复发放积分。
- 到期、取消和下周期生效转换正确。
- 权益检查不能绕过服务端权限。

### 13.3 订单与支付

- 客户端篡改金额无效。
- 重复创建请求复用订单或返回同一结果。
- 重复支付回调不重复发放权益。
- 失败、关闭和取消订单不能发放权益。
- 未配置支付适配器时付费流程 fail closed。
- 退款使用冲正流水且历史可追溯。

### 13.4 运行时

- 余额不足时模型调用不会启动。
- 取消、超时和异常调用正确释放预占。
- 调用价格使用开始时版本快照。
- 缓存输入、普通输入和输出分别计价。
- 未返回用量的调用不猜测扣费并产生告警。
- 任务聚合用量与单次调用明细可以对账。

### 13.5 页面

- 使用 Codex 内置浏览器逐页验收全部后台和 C 端路由。
- 与 Nuwax 参考页面对比信息结构、字段和交互闭环。
- 使用 Coze 统一设计系统验证桌面与移动宽度。
- 验收加载、空态、错误、无权限、禁用、刷新和危险操作状态。
- 控制台无新增错误和未处理 Promise。
- 键盘焦点、表单校验、弹窗关闭和 ARIA 行为正常。

### 13.6 安全与隔离

- 普通用户访问管理员 API 返回服务端 `403`。
- 用户不能读取其他用户的余额、订单和订阅。
- 跨租户 ID 组合不能命中数据。
- API、日志和页面不回显密钥或内部敏感数据。
- 所有人工调整都有操作者、原因和审计记录。

## 14. 实施约束

- 后端保持 Go-native 和现有 DDD 分层。
- IDL 有生成客户端时不新增手写前端 fetch。
- 数据库变更使用 Atlas migration 并校验 hash。
- 不复用 Nuwax Java 代码，只迁移已核实的业务合同和用户体验。
- 不使用内存 stub 作为生产数据源。
- 不在一个变更中同时开启强制扣费和真实支付。
- 每个阶段完成 targeted tests、迁移校验和内置浏览器页面验收后才能进入下一
  阶段。
